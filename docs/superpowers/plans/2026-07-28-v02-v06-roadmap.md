# Today Mayor v0.2-v0.6 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade the mobile city-management game from a static alpha into an animated, event-driven, cloud-capable v0.6 release.

**Architecture:** A dependency-free ES module front end is deployed from `site/` on Cloudflare Pages. Pure game rules live in `site/js/engine.js` and content in `site/js/content.js`; Pages Functions under `functions/` provide optional D1-backed authentication, cloud save, national choice statistics, and ranking while the client retains an offline local fallback.

**Tech Stack:** HTML, CSS, SVG, browser ES modules, Node.js built-in test runner, Cloudflare Pages Functions, Cloudflare D1.

## Global Constraints

- Mobile-first layout with a 520px maximum content width.
- No mandatory third-party runtime packages.
- The game remains fully playable when Cloudflare D1 is not configured.
- Each version must be independently testable and committed separately.
- Character art must read clearly as a tanuki: round muzzle, dark eye mask, rounded ears, large striped tail, navy municipal uniform, leaf cap.
